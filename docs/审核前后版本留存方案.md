# 审核前后版本留存方案

本方案定义会议纪要及结构化观点在人工审核前后的通用版本留存规则。

## 目标

- 保存首次进入人工审核时的不可变基线。
- 保存审核通过后的正式归档版本。
- 记录两个版本的文件 token、版本号、SHA-256 和业务记录关系。
- 确保下游只消费当前审核通过版本。

## 状态流转

生成待审核 Markdown → 固化审核前基线 → 人工编辑与确认 → 归档审核后版本 → 校验远端字节与哈希 → 更新 Base 指针 → 清理旧的非权威产物。

## 并发与幂等

每个任务绑定会议 ID、数据版本和输入哈希。写入前重新读取 Base；若记录版本已经变化，当前任务必须停止。重复处理同一输入时应返回已有产物，不得制造相互冲突的正式版本。

## 部署要求

字段名和资源标识通过统一契约与部署配置提供。部署者应在测试 Base 中验证审核前基线、审核后归档、过期任务拦截、失败重试和旧版本清理。
