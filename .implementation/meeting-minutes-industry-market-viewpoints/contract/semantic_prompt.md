# 行业与市场观点抽取提示

只依据给定会议纪要及其 source fragments 生成 claim units。完整阅读全文，
按以下顺序处理，并只输出严格匹配 `claim_units.schema.json` 的 JSON 数组。

纪要可能带有“脱敏”“演示”“虚构示例”或“不构成投资建议”等数据性质声明。
这类声明只描述材料用途，不否定正文中已经表达的判断，也不能作为返回空数组的理由；
仍须按正文语义抽取市场和行业观点，无需判断实体是否真实存在。

## 范围

每个 claim unit 表示一个“发言人 × 主题 × 独立判断”。

- `view_scope=market`：市场整体、指数环境、风格、流动性、估值、风险偏好或市场级交易条件。
- `view_scope=industry`：行业、板块、产业链或跨公司主题。
- 排除纯事实、会议流程、无方向的事件关注，以及只针对单一证券自身的判断。
- 不得把多个证券判断概括为原文没有表达的市场或行业结论。
- 证券或企业信息可以作为行业判断的依据，但最终判断对象必须是市场或行业。
- 单一证券相关陈述中若同时包含可独立成立且原文明示的市场、行业、板块、
  产业链或跨公司主题判断，只提取该主题判断，不携带或扩展证券层面的结论。

## 生成顺序

1. 先分别盘点全文中的市场判断和行业判断，记录发言人、主要对象、方向、重要时间范围、实质条件或限制和 source refs。
2. 在忠实表示每项判断后，再确定最小完整对象并规范主题。
3. 按对象、方向、时间范围、发言人和原文位置决定合并或拆分。
4. 将保留的判断压缩为独立可读的一至两句话。
5. 对完整结果执行遗漏、准确性、对象一致性、范围归属和可读性复核，修正后再输出。

## 准确性

- 保持观点对象、核心方向、重要时间范围和实质结论不变。
- 允许删除口头语、重复推导、次要背景和不影响核心方向的限定。
- 不得新增原文没有的事实、数字、实体、因果关系或方向。
- 不得把预期改写成已经发生的事实，不得把可能结果改写成必然结果。
- 不得把短期判断扩大为长期趋势，也不得删除足以改变核心方向的条件。
- 只有在不改变判断状态、成熟程度、适用范围、时间边界或实际含义时，才可删除限制性信息。
- 每个事实、方向、时间和因果表述都必须得到所选 source refs 的支持。
- `source_refs` 使用输入 source fragments 的稳定 ID，并按原文顺序排列。
- `presenter` 保持原始发言人文本。不同发言人的判断保持分开。

## 主题

- `subject` 必须对应观点实际讨论的最小完整对象。
- 优先采用通行、稳定、可长期复用的市场、行业、板块或产业链名称。
- 去除事件、时间、方向、结论、催化和交易动作，不把完整判断写入主题。
- 相同概念尽量复用同一主题；只有分析对象存在实质差异时才拆分主题。
- 只有已有主题会造成明显语义损失时才创建新主题。
- 不得为了减少主题数量而把不同对象强行归并。
- 中文主题通常控制在 2—10 个字；确有必要时可以更长，但仍须简洁。

## 观点类型

- `view_type` 只能是 `看多`、`看空`、`中性`。
- 根据预期结果的核心方向分类：整体正向为 `看多`，整体负向为 `看空`，方向不清或多空平衡为 `中性`。
- 概率、推测和不确定语气通常不改变方向分类，不得仅因存在概率措辞而机械归为 `中性`。
- 概率措辞可以适度简化，但仍须遵守准确性要求，不得改变事实状态、必然程度或时间范围。
- 只有事件、催化或关注表述而没有市场或行业方向判断时，不生成观点。

## 合并与拆分

- 同一发言人、同一主题、同一方向、原文相邻且共同构成完整逻辑的判断优先合并。
- 对象、方向、重要时间范围、发言人或判断逻辑不同的内容保持分开。
- 每条观点只保留一个主要判断对象；辅助内容仅在直接解释该对象且不形成独立结论时保留。
- 具有独立意义的并列结论应分开，单纯支撑主要结论的理由不得机械拆分。
- 不得合并距离较远、仅因主题相近而实际逻辑独立的内容。
- 不得把一个完整逻辑拆成缺乏独立信息的碎片，也不得重复输出同一观点。

## 范围归属

- 市场判断和行业判断分别归入对应范围，不在同一观点中混合不同层级的独立结论。
- 跨范围内容能够独立成立且符合准入条件时分别生成；不能独立成立时仅保留与主要对象直接相关的内容。
- 事件相关内容只有在原文明确定向市场或行业结果时才能保留；结果未定、方向相互抵消或仅描述事件与资金行为时不生成观点。

## 可读性

- `viewpoint_text` 必须明确观点对象，使用完整句子，并能脱离原文独立理解。
- 消除无法在当前卡片内解析的指代，以及依赖未展示前文的转折、因果或承接关系。
- 优先表达核心判断，再保留最必要的原因、时间或限制。
- 删除会议流程、发言过程、无信息量前缀和不影响理解的细节。
- 避免空泛结论、过度压缩、术语堆积和无法解释的简称。
- 每条观点应具有足以支持看板阅读的实际信息量，同时保持一至两句话的简洁长度。
- 原文明示方向但未提供充分理由时，可以保留简短观点，但不得补充原文没有的依据。

## 输出前复核

- 检查全文是否遗漏明确的重要市场或行业判断。
- 检查主题与正文对象是否一致并可长期复用。
- 检查观点类型是否反映核心方向。
- 检查每条观点是否只有一个主要对象并归入正确范围。
- 检查是否扩大了观点范围或改变了原文的实质结论。
- 检查重要条件和限制是否得到保留。
- 检查是否包含仅由事件、资金行为或未定结果构成的内容。
- 检查是否存在重复、错误合并或不必要拆分。
- 检查每条观点是否可以独立阅读且信息完整。
- 返回空数组前必须再次阅读全文和 source fragments，确认不存在由明确主题、判断和
  原文证据共同支持的市场或行业观点；不得因为观点与证券陈述处于同一语境而一并丢弃。

不要输出解释、盘点过程、自检过程或 Markdown。
